# Reload preserves the instance; host shutdown ends it

A config reload changes the policy view while keeping the Vault, Sent forms, active streams and Masking records. When the host calls shutdown, Veil closes call admission, waits for admitted calls and configuration work, finishes stream counts, drains and stops the record writer, then releases the instance. A later initialization creates a new Vault even when CPA keeps the shared library mapped. Persisted keys and records remain, but provider-held Placeholders need original values masked again before they restore (ADR-0001).

CPA calls shutdown when disabling or uninstalling a plugin. The plugin does not infer lifecycle events from idle time or a reconfigure call.

Masking records have an acceptance order shared with clear and directory changes. Clear removes records accepted before its cutoff in the current directory, including queued writes, and invalidates their late restore counts. A directory switch finishes earlier records in their original directory, records later requests in the new one, and makes the management page show only the new directory. Restore counts follow the original record across switches and revisits; old files are neither moved nor cleared by operations on the new directory.

The ABI preserves the Host's RequestID for request, response and stream hooks. Restore counts consume the association for the Caller scope and request ID, and nothing else associates a response with a request: a call that names no request, or one Veil does not know, has no Masking record. Its response is still restored, a stream's chunks each on their own with no Held tail, and no count is kept.

Revised on 2026-11-11: Veil used to fall back to matching request bodies on a Host without request IDs (CPA v7), with rules for bodies that matched more than one request and for a full cache. Veil works with CPA v8 only now (ADR-0002), and the fallback is gone with its rules.

Revised on 2026-11-11: a Masking record is one Round trip's, not one Pass's. The Host hands a request to Veil before it picks a credential and again for each credential it tries, and text another plugin adds in between used to leave a second record that no response ever counted into. The first Pass that finds something writes the record; a later Pass adds the values the record does not have, each value once however many Passes find it, and says so if it stopped the request. A Pass before the Host picks a credential starts a Round trip, so a request sent again, and each turn on a connection that carries several under one request ID, has a record of its own.

A Round trip's restore counts are written once, when it ends: with a whole response, with the event that ends its stream, with the next Round trip of its request ID, or when the Host says the request is complete (`request.complete`), which also releases what Veil held for the request ID. A response that restored nothing still writes its empty counts, which is how a record says its response came; a request that got no response writes none. Ten idle minutes end a Round trip the Host never completed. The plugin still does not infer the instance's lifetime from idle time.

A day's file writes what a later Pass adds as a patch line, as restore counts already were: the record's key, `patch`, and the added values. A version of Veil from before this revision reads such a line as a patch without restore counts and skips it, so it shows the record as its first Pass left it.

Requests do not wait for record I/O: the bounded queue still drops and counts excess submissions. Once calls have drained during shutdown, final stream counts may wait for space so disposal finishes those counts before joining the writer. The rule against retaining original values stays unchanged (ADR-0005).
