# Reload preserves the instance; host shutdown ends it

A config reload changes the policy view while keeping the Vault, Sent forms, active streams and Masking records. When the host calls shutdown, Veil closes call admission, waits for admitted calls and configuration work, finishes stream counts, drains and stops the record writer, then releases the instance. A later initialization creates a new Vault even when CPA keeps the shared library mapped. Persisted keys and records remain, but provider-held Placeholders need original values masked again before they restore (ADR-0001).

CPA v8.0.52 calls shutdown when disabling or uninstalling a plugin. CPA v7.1.70 config disable only removes capabilities from dispatch and keeps the loaded client; re-enable calls reconfigure on it. Veil receives no disable notification on v7, so it cannot release that instance or distinguish re-enable from a policy reload. Changing the key on v7 therefore needs a CPA restart or an actual host shutdown operation. The plugin does not infer lifecycle events from idle time or a reconfigure call.

Masking records have an acceptance order shared with clear and directory changes. Clear removes records accepted before its cutoff in the current directory, including queued writes, and invalidates their late restore counts. A directory switch finishes earlier records in their original directory, records later requests in the new one, and makes the management page show only the new directory. Restore counts follow the original record across switches and revisits; old files are neither moved nor cleared by operations on the new directory.

The ABI preserves CPA v8's RequestID for request, response and stream hooks. Restore counts consume the association for the Caller scope and request ID; an unknown ID never falls back to a body match. Without IDs, only an unambiguous scoped body may associate a response. Overlapping identical bodies or multiple matching body candidates permanently invalidate that body association until the instance ends, including when one request has no Masking record. The bounded legacy cache keeps those invalidations; on saturation it stops all legacy association until a new instance starts, because evicting a pending body would let a late response take a newer record. Lost associations skip restore counts, without changing masking, response restoration or record creation.

Streams without request IDs also discard their final tallies if an identical stream opens while they are active. Their record associations may have already been consumed at header-init, but their chunks still cannot be attributed reliably. Complete Placeholders continue to restore under the existing ambiguous-stream behavior.

Requests do not wait for record I/O: the bounded queue still drops and counts excess submissions. Once calls have drained during shutdown, final stream counts may wait for space so disposal finishes those counts before joining the writer. The record format and the rule against retaining original values stay unchanged (ADR-0005).
